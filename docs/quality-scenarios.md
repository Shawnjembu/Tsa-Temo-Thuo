The listing may also contain existing reserved or confirmed stock.* **Expected response:** The system processes the requests atomically so that available stock cannot become negative and the combined reserved and confirmed quantities never exceed the listing's total quantity. Only orders that can be fully supported by available stock are accepted.* **Measure:** 0 oversell states across 100 simulated concurrent-order test runs (automated test, ties to AC-04).### QS-02 — Listing search performance* **Stimulus:** A buyer submits a search filtered by crop and district.* **Context:** Catalogue of 500 synthetic Active listings, using a typical mobile connection.* **Expected response:** The system returns the matching available listings to the buyer without displaying expired or sold-out listings as available for ordering.* **Measure:** 95th-percentile response time under 2 seconds, measured server-side across 50 repeated searches.### QS-03 — Reliability under dropped connectivity (rural network conditions)* **Stimulus:** A buyer's device loses connectivity after submitting an order but before receiving the confirmation response, then reconnects and retries the request.* **Context:** Intermittent rural connectivity, as identified in the proposal assumptions. The retry uses the same idempotency token as the original request.* **Expected response:** The system recognises the retry as a duplicate request and returns the original order state without creating another order or another stock reservation.* **Measure:** 0 duplicate orders and 0 duplicate reservations across 20 simulated drop-and-retry test runs. (Automated test; ties to AC-05.)### QS-04 — Usability of order placement* **Stimulus:** A first-time buyer with no prior training attempts to find and order a specific crop.* **Context:** Synthetic buyer account, mobile-sized screen, with no external assistance.* **Expected response:** The buyer can search for the required crop, select an available listing, enter a valid quantity and reach the order confirmation without unnecessary navigation.* **Measure:** Task completed in 5 or fewer screens by at least 4 of 5 synthetic-user walkthroughs, consistent with the proposal's Objective 3.### QS-05 — Authorisation of order confirmation* **Stimulus:** A user who is not the owning farmer attempts to confirm or reject an order belonging to another farmer's listing through the application or by manipulating a direct API/URL request.* **Context:** The user is authenticated as a different verified farmer, buyer or other unauthorised account.* **Expected response:** The system rejects the action and does not change the order state or stock quantities.* **Measure:** 100% rejection rate across all unauthorised confirmation and rejection attempts in the automated authorisation test suite, with 0 successful unauthorised state changes.#### ### QS-06 — Stock restoration after rejected, cancelled or expired orders* **Stimulus**: An order holding reserved stock is rejected by the farmer, cancelled by the buyer or reaches the end of its reservation period without confirmation.* **Context:** The order has already moved the requested quantity from available stock to reserved stock.* **Expected response:** The system releases the reserved quantity when the order is rejected, cancelled or expires. The released quantity is returned to available stock and is no longer associated with the closed order's reservation.* **Measure:** 100% of tested rejected, cancelled and expired orders release their reserved quantities correctly, with no permanently locked stock and no change to the listing's total quantity.### QS-07 — No double deduction when an order is confirmed* **Stimulus:** A farmer confirms an order after the requested quantity has already been reserved.* **Context:** The order has a quantity recorded as reserved and the listing has a separate available quantity.* **Expected response:** The system transfers the quantity from reserved stock to confirmed stock without deducting the same quantity from available stock a second time.* **Measure:** 100% of confirmation tests preserve the stock equation Available + Reserved + Confirmed = Total, with 0 cases of double deduction or negative available stock.### QS-08 — Produce-quality information and responsibility* **Stimulus:** A buyer views a produce listing before placing an order and later reports that the delivered produce does not match the quality or grade declared in the listing.* **Context:** The listing contains farmer-declared produce type and grade/quality information. The system has not independently inspected the physical produce.* **Expected response:** The system displays the quality information supplied by the farmer before ordering and identifies the relevant farmer/listing when a quality issue is reported. The system does not represent the platform as independently guaranteeing the physical quality of the produce.* **Measure:** 100% of tested listings display the farmer-declared quality/grade information before ordering, and every tested quality complaint can be associated with the relevant farmer, listing and order.### QS-09 — Recoverability of order history after failure* **Stimulus:** The application server restarts or crashes immediately after an order reaches the Confirmed state.* **Context:** Simulated mid-operation failure during normal load.* **Expected response:** On restart, the order's state and full history are exactly as they were before the failure — no state is lost or left ambiguous.* **Measure:** 100% of order records match their pre-failure state and history across 10 simulated crash-and-restart test runs.### QS-10 — Stock consistency across the complete order lifecycle**Stimulus:** A set of orders progresses through placement, confirmation, rejection, cancellation and reservation expiry.**Context:** The listing contains available, reserved and confirmed quantities and multiple order outcomes are tested.**Expected response:** Stock quantities remain consistent throughout the lifecycle. Reservations reduce available stock once, confirmations transfer reserved stock to confirmed stock, and rejected, cancelled or expired reservations are returned to available stock.**Measure:** 100% of lifecycle tests maintain the following rules:Available + Reserved + Confirmed = TotalandReserved + Confirmed ≤ Totalwith 0 negative-stock states, 0 oversell states and 0 double deductions.
